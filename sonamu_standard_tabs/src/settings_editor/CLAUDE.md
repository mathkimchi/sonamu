# Settings editor (#107)

Native applet `settings_editor` for newcomers: every setting as a form, applied as it changes. Opened by the hub's Settings row (`BarAction::OpenSettings` → `BarRequest::Open`), `sonamu-msg open settings_editor`, `sonamu.open`.

- `form.rs`: fields from `settings::schema()` (bool → toggle, number → clamped to `minimum`/`maximum`, enum → choice, `Color` → swatch, `string|null` → text (empty = null), `format: path` (`#[schemars(extend("format" = "path"))]`) → file, string list → item rows, else read-only). Colors first; object settings get sections; the rest is "General". New settings show up without editing it. Variants (a `oneOf` of strings and one-key objects, eg `wallpaper`) are a kind choice followed by the current kind's fields; `sections` is rebuilt from the values after each change (`Editor::refresh`). A field the settings leave out shows the schema's `default` (`Editor::field_value`).
- `editor.rs` (`Editor`): edits the user's raw JSON via `sonamu_common::settings_file` (only what differs from the defaults is kept; unknown keys and order stay). Re-reads the file before each write, so hand edits survive. Revert writes the file as it was at open (deletes it if there was none; refused if it couldn't be read). An executable `settings` makes it read-only.
- `keybinds.rs`: the Keybinds section's groups and `Draft`s. Unfinished binds (no keys, bad args) stay in the editor but aren't written; binds it can't represent (unknown command, extra keys, args written otherwise) are kept `raw` and written back as they were. A flat list (before groups) becomes group `Keybinds` (`settings_file::migrate`). External changes are seen by comparing the file's keybinds as text (`keybinds_changed`: maps compare without order). Records keys by holding a `sonamu_common::Capture` (`KEY_CAPTURE`: runner and root skip their bindings); dropped on Esc, the recorded key or close; the root/runner end it when focus leaves (see `.claude/COMMANDS.md`).
- `pastel.rs`: seven colors from one random hue.
- `mod.rs`: rows from `form_rows` (sections fold by their title; the color picker's `PICKER_LINES` sit under its field). Numbers: −/+ (Left/Right) step by `ui::fields::step_size`, bounded ones get a slider; colors open `ui::color_picker` (drag previews, written on release; Esc writes the old color back). The picker is drawn over its lines, outside any row (rows clip their children). Files open `ui::file_chooser` below the field ("type a path" first); picked files are written with `settings::config_relative`.
- Treeview: each section (Keybinds last) is an inner child (`section_tree`), like the file manager's documents. Focus is `view`: the inner root shows every section, a section's row shows it alone (no title, never folded; `‹ Settings` / Esc / swipe up go back, swipes left/right move between sections, drawn with `swipe::slide` from `StandardEvent::Swipe`). In the full view: double click or Right on a title shows it alone (`show`), `toggle_collapsed` folds it. Sections aren't nodes: dragging one moves the whole editor, its close button does nothing.
- Variant changes (cycle, external edits) can drop fields: `close_stale` closes a picker or chooser whose field is gone.
- Gotcha: hit-testing uses the size as last drawn (`size: Cell`); `WindowResized` doesn't always come.
- One editor: `OPEN` holds its `NodeUid`; opening again sends it `focus`.
- Writes reach Sonamu through the settings watcher (`settings_changed` → `Editor::reload`, `sync_keybinds`).
